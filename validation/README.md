# Fork compatibility review — 2026-09-25 UTC

Baseline: `0xfnzero/sol-parser-sdk` commit `f60ace491921324ac0163eae7d7e30968d581f68` (0.7.6). This fork is a reviewed patch set, not a certification that every parser or dependency is safe.

## Corrected findings

- Pump bonding curves rejected complete historical layouts. The decoder now accepts complete bodies of 41, 73, 74, 75, 107, 115 and 116 bytes, or the current 117-byte body with optional allocation padding. Missing historical fields default to zero; partial fields are rejected.
- PumpSwap pools rejected complete historical layouts. Bodies of 203, 235, 236, 237, 253, 261 and 262 bytes are supported alongside the current 263-byte body and larger allocations. The legacy 244-byte allocation is accepted only with zero padding after byte 237. This avoids mistaking a truncated nonzero virtual-reserve field for an old pool.
- Direct nonce decoding accepted arbitrary 80-byte accounts. Both direct and unified paths now require a nonexecutable System Program account with the current initialized nonce discriminator and exactly 80 bytes. This deliberately does not treat legacy-version nonces as current usable durable nonces.
- Pump transaction strings reached `from_utf8_unchecked` with unvalidated bytes. Strings now use checked ranges and UTF-8 validation. A present malformed trade name is rejected rather than shifting the subsequent field offsets.

These reproduce relevant changes in the owner's Node fork (`realhen/sol-parser-sdk-nodejs`, commits `15be60d` and `e739857`). Browser module packaging changes do not apply to Rust.

## Independent evidence

The official [Pump documentation](https://github.com/pump-fun/pump-public-docs) links `@pump-fun/pump-sdk`. The oracle uses exactly `@pump-fun/pump-sdk` 2.0.0 and `@pump-fun/pump-swap-sdk` 1.20.0, with npm integrity hashes in `package-lock.json`. It uses their own account and event decoders, not copied Rust offsets.

`fixtures/mainnet-2026-09-25.json` contains ten successful public transactions captured at slots 450216892 and 450216897, plus account snapshots at slots 450216900 and 450216901. The expected file is regenerated by the official SDKs. It compares trade amounts, fees, reserves, users/pools/mints and slot metadata, plus 21 historical/current/padded account variants. Historical variants are controlled truncations/extensions of the live snapshots, not claims that those shorter accounts were observed in that capture.

The 256-byte live curve is `Ef796zSZV6YHjCYSZJ4fzw5o1nb9Lquh1yWxAQsu9Kv9` for mint `4dgLcGttZ2nzza3ZM7BUAEubN7MxoeMpqf7LUgyspump`. Upstream 0.7.6 already accepted its padding; the engine's separate exact-size allowlist caused the reported rejection. Engine wrappers must also be changed before that user-facing bug is fixed.

```sh
RUN_MAINNET_TESTS=1 cargo +1.97.1 test --locked --test current_mainnet_transactions
```

The last command reads public transactions from `SOLANA_RPC_URL` (or public mainnet RPC). It does not sign or submit. On this review: four offline integration workflows passed, 286 existing library checks passed, and all 12 gated mainnet replay workflows passed. That existing corpus additionally covers Raydium AMM/CPMM/CLMM/LaunchLab, Meteora DAMM v2/DLMM, Orca and StonkFun attribution. Those other venues have not received an independent official-SDK parity audit here.

## Boundaries

The account decoder's owner check belongs to `parse_account_unified`; direct protocol account decoders still require a trusted caller to validate owner. Callers must independently enforce freshness, commitment, account relationships and supported token extensions. These tests do not establish live stream reconnection, reorg handling, signing safety, transaction landing or economic quote accuracy. Unsafe low-level/performance APIs elsewhere remain outside this patch's approval. Use the default Borsh backend until separately reviewed; no blanket approval is given to `ultra-perf` or zero-copy backends.
